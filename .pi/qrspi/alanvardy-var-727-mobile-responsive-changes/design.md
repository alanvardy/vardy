# Design Discussion

## Current State

The site is a Rust/axum + minijinja + Tailwind v4 CSS-first application with four
templates and a single CSS source file. All responsive behavior is driven by one
breakpoint (`md`, 48rem / 768px) with no hand-written `@media` queries — every
`@media` block in the compiled `static/site.css` is generated by the Tailwind v4.3.3
CLI (`research.md` Q4 audit).

### Contact form on mobile (< 768px)

The contact page wrapper uses `flex flex-col md:flex-row gap-8 items-start`
(`templates/contact.html:5`). The form column carries `md:flex-1` but no base width
(`templates/contact.html:18`). On mobile the wrapper stacks vertically; `items-start`
prevents cross-axis stretching, so the form column sizes to its intrinsic
max-content — measured at ~202px (`research.md` Q2 column-width findings). The
intro column fills the wrapper, creating a lopsided two-column appearance below
768px where the form is squeezed into roughly 202px on the right.

### Wallpaper and credit on mobile

The `.wallpaper` div (`templates/layout.html:14`) and credit bubble
(`templates/layout.html:18-21`, guarded by `{% if photographer %}`) render
unconditionally on every viewport. The `.wallpaper` base rule
(`css/site.css:60-67`) sets `position: fixed; inset: 0; z-index: -1` with no
display toggling. The credit bubble uses `fixed bottom-3 right-3` and is always
visible when a photographer is set.

### Existing patterns

- **Mobile-first two-column**: `flex flex-col md:flex-row` is the canonical pattern
  used identically across `templates/home.html:8`, `templates/contact.html:5`, and
  `templates/singlethread.html:7` (`research.md` Q4).
- **`md:` as the sole breakpoint**: zero occurrences of `sm:`, `lg:`, `xl:`, or
  `2xl:` anywhere in `templates/` or `css/` (`research.md` Q4 `@media` audit).
- **No hand-written `@media`**: VAR-719 design doc codified "Not introducing media
  queries beyond Tailwind's built-in breakpoints" (`research.md` Q4 prior docs).
- **CSS-only presentation changes**: prior features (VAR-719, VAR-726) kept layout
  logic in templates and CSS — no handler plumbing for presentation concerns
  (`research.md` Q4 prior docs).
- **Drift gate**: `scripts/test.sh:12-13` runs `build-css.sh` then `git diff
  --exit-code -- static/site.css` — any new utility class added to a template must be
  accompanied by the regenerated committed `static/site.css` (`research.md` Q5).

## Desired End State

Two presentation-only changes, neither requiring handler or backend changes:

### 1. Contact form spans full width on mobile (< 768px)

The form column is full-width on mobile, auto on desktop where `md:flex-1` takes
over. Two-column split remains identical at ≥768px.

**Verification**: below 768px the form column spans the full container
content-width (viewport − 2rem padding). At ≥768px the existing two-column
`md:flex-1` split is unchanged. The test at
`src/interfaces/handlers/contact/web.rs:64-88` (`get_contact_returns_200_with_form`)
continues to pass with no changes needed.

### 2. Wallpaper background and credit bubble hidden on mobile (< 768px)

The `.wallpaper` div and credit bubble are `display: none` below 768px,
`display: block` at 768px and above. Template conditionals (`{% if wallpaper_url
%}`, `{% if photographer %}`) are unchanged.

**Verification**: below 768px no wallpaper image or credit text renders. At ≥768px
the wallpaper and credit bubble render identically to today. Existing wallpaper
tests in `src/interfaces/handlers/home/web.rs` and
`src/interfaces/handlers/singlethread/web.rs` pass unchanged (they don't assert
display or visibility). The three Unsplash-failure suppression paths
(`research.md` Q3 table) all continue to work — empty `wallpaper_url`/`photographer`
still suppress the wallpaper style and credit bubble regardless of `hidden md:block`.

## Patterns to Follow

| Pattern | Location | Application |
|---|---|---|
| Mobile-first `flex flex-col md:flex-row` | `home.html:8`, `contact.html:5`, `singlethread.html:7` | Already in place — we build on it |
| `md:` as the exclusive responsive breakpoint | Every responsive utility in `templates/` | Use `hidden md:block` for wallpaper, `w-full md:w-auto` for form |
| CSS-only layout changes, no handler plumbing | VAR-719 design doc (`research.md` Q4) | No changes to handlers, `wallpper_context`, or render `context!` calls |
| `w-full` + `md:` override as the width-control idiom | `home.html:40` (`max-w-[200px] md:flex-1` — base width constraint + md: override) | `w-full md:w-auto md:flex-1` on the form column follows this pattern |
| Asset references through `asset_url` | `layout.html:11`, every template | No changes to asset references |
| Test assertions via `body.contains(...)` substring checks | `contact/web.rs:64-88`, `home/web.rs:43-63`, `singlethread/web.rs:112-131` | No layout-specifific assertions to update on contact form — tests pin content, not CSS classes |
| Drift gate: regenerate + commit `static/site.css` | `scripts/test.sh:12-13`, `ci.yml:145-146` | Must run `scripts/build-css.sh` and commit the result after adding utility classes |
| Component classes in `@layer components`, base chrome in `@layer base` | `css/site.css:108` (components), `:29` (base) | No new @layer rules needed — both changes are template-only utility classes |

### Patterns NOT to follow

- **`.container-wide`**: planned in VAR-719 design doc but never implemented
  (`research..md` Q5 open areas). Do not introduce it here; these changes don't need it.
- **Hand-written `@media` queries**: removed in VAR-682 Tailwind v4 migration
  (`research..md` Q4). Use Tailwind breakpoint utilities only.
- **Template conditionals for layout**: the `{% if %}` guards on `wallpaper_url` and
  `photographer` are existing content-driven branching. Do not add new `{% if %}` for
  device-responsive behavior; use CSS utilities.
- **Handler-level responsive flags**: passing device or viewport state from handlers
  adds coupling between presentation and backend. All responsive behavior stays in CSS.

## Design Decisions

1. **Breakpoint**: `md` (768px) — chosen over introducing `sm` (640px) because the
   codebase uses `md:` exclusively as its canonical responsive breakpoint
   (`research.md` Q4 audit). Tablet users at 640–767px will also see the mobile
   treatment; this is acceptable given the site's simplicity and the absence of
   tablet-specific optimizations anywhere else.

2. **Form column fix**: `w-full md:w-auto` on the form column
   (`templates/contact.html:18`) — `w-full` stretches the column to the full
   container width in the stacked mobile layout, where `items-start` prevents
   cross-axis stretching. `md:w-auto` restores auto-sizing at ≥768px so `md:flex-1`
   dictates the column split. This is explicit, minimal (2 utility classes), and
   doesn't touch the wrapper alignment — the intro column's behavior is unchanged.

3. **Wallaper hiding**: `hidden md:block` on both the `.wallpaper` div
   (`templates/layout.html:14`) and the credit bubble div
   (`templates/layout.html:18`) — CSS-only, no new template conditionals. Tailwind's
   `hidden` (display: none) and `md:block` (display: block at min-width 48rem) are
   standard utilities. Both elements stay in the DOM at all viewports; the existing
   `{% if %}` guards still control content presence entirely.

4. **No new @layer rules**: both changes are template-side utility-class additions.
   The compiled `static/site.css` picks up `hidden`, `md:block`, `w-full`, and
   `md:w-auto` through Tailwind's source scanning. No hand-written CSS is needed.

5. **No test changes required**: the contact form test asserts form field names,
   action, and nav — no CSS classes (`research.md` Q2 test assertions). The
   wallpaper tests assert content presence (linked photographer name, url() in
   inline style, absence on failure) — no display or visibility assertions
   (`research.md` Q3 test assertions). The drift gate catches the compiled CSS delta
   without explicit test additions.

## What We're NOT Doing

- Not changing the container width, `.container` base rule, or any `@theme` tokens
- Not introducing `sm:`, `lg:`, or any new breakpoint
- Not adding `.container-wide` or any new component class
- Not modifying handler code, `wallpaper_context`, or render context
- Not changing the nav bar, heading, or any other chrome
- Not touching the home page or singlethread page
- Not adding hand-written `@media` queries
- Not restructuring template markup (no new divs, no DOM changes)
- Not removing or changing `items-start` on the contact wrapper
- Not modifying the Unsplash fetch/cache fallback logic
- Not changing any other page's layout

## Open Risks

1. **Hidden credit on mobile — Unsplash attribution**: the Unsplash API terms require
   attribution. Hiding the credit bubble on mobile means no attribution on phone-sized
   screens, where the wallpaper itself is also hidden. Since the wallpaper image is
   not displayed on mobile either (`display: none`), this should satisfy the
   attribution requirement (no image shown → no credit needed).

2. **`md:block` on the wallpaper div vs orchestrated z-indx**: the `.wallpaper`
   class sets `z-index: -1; position: fixed` in `@layer base`. When `hidden` (from
   `@layer utilities` with higher precedence) sets `display: none`, all other
   properties are inert. When `md:block` restores `display: block` at ≥768px, the
   original base properties resume. Tailwind's `block` utility sets only `display:
   block` — it does not touch `z-indx` or `position`, so the wallpaper's stacking
   context is preserved.

3. **Credit bubble stacking context**: the bubble uses `fixed bottom-3 right-3`
   utilities from the utils layer. `hidden` adds `display: none`; `md:block` adds
   `display: block` at ≥768px. No `position` or `z-indx` change — works identically
   to the wallpaper fix.

4. **`w-full` + `md:w-auto` + `md:flex-1` collision**: in a `md:flex-row` context
   at ≥768px, `md:w-auto` (width: auto) and `md:flex-1` (flex: 1) coexist cleanly
   — `flex: 1` sets `flex-basis: 0%` and `flex-grow: 1`, while `width: auto` is
   overridden by the flex algorithm for grow-capable items. Below 768px in a column
   context, `w-full` (width: 100%) sets the column to full container width and
   `md:flex-1` is not yet active.

5. **CSS drift gate**: adding `hidden`, `md:block`, `w-full`, and `md:w-auto` to
   templates will cause `scripts/test.sh` to fail until `scripts/build-css.sh` is
   run and the regenerated `static/site.css` is committed. `hidden` and `w-full`
   likely already exist in the compiled output (they are base utilities), but
   `md:block` and `md:w-auto` may be new to the `md:` variant group since no current
   template uses them. Regardless, the process is: run `build-css.sh`, commit the
   updated `static/site.css`.
