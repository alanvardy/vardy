# Structure Outline

## Approach

Two CSS-only responsive fixes at the `md` breakpoint (768px), applied entirely in
templates via Tailwind utility classes. The contact form column gains `w-full
md:w-auto` so it spans full width on mobile; the wallpaper and credit bubble gain
`hidden md:block` so they render only at ≥768px. No handlers, routes, store
methods, or schema changes. The bottom layer is template markup; the compiled
`static/site.css` is the derived layer on top.

---

## Stage 1: Template markup — utility class additions

Add four utility classes across two templates. These are the "source of truth" for
the Tailwind utility scan; the compiled CSS in Stage 2 is a derived artifact.

**Files**: `templates/contact.html`, `templates/layout.html`

**Key changes**:

- `templates/contact.html:18` — form column div:
  - Before: `<div class="md:flex-1">`
  - After:  `<div class="w-full md:w-auto md:flex-1">`
  - `w-full` (width: 100%) stretches the form column to full container width in
    the stacked mobile layout where `items-start` prevents cross-axis stretching.
    `md:w-auto` restores auto-sizing at ≥768px, allowing `md:flex-1` to control
    the column split.

- `templates/layout.html:14` — wallpaper div:
  - Before: `<div class="wallpaper" aria-hidden="true" ...>`
  - After:  `<div class="wallpaper hidden md:block" aria-hidden="true" ...>`
  - `hidden` sets `display: none` on all viewports; `md:block` overrides to
    `display: block` at ≥768px. Existing `{% if wallpaper_url %}` guard still
    controls the inline `style` attribute.

- `templates/layout.html:18` — credit bubble div:
  - Before: `<div class="fixed bottom-3 right-3 px-3 py-1.5 rounded bg-black/50 text-sm">`
  - After:  `<div class="hidden md:block fixed bottom-3 right-3 px-3 py-1.5 rounded bg-black/50 text-sm">`
  - Same `hidden md:block` pattern. Existing `{% if photographer %}` guard still
    controls content presence.

**Tests**: None added — no test in the repo asserts CSS classes on the form column
or `display`/visibility of the wallpaper/credit bubble (`research.md` Q2, Q3).
Existing tests continue to pass (they assert content strings, not CSS).

**Verify**:
- Manual: `git diff -- templates/` shows the four utility-class additions with no
  other template changes.
- Manual: visual inspection of the diff confirms `w-full md:w-auto`, `hidden
  md:block` × 2, and no unintended markup changes.

**Note**: The project test gate (`scripts/test.sh`) will **fail** at this stage
because the CSS drift check (`git diff --exit-code -- static/site.css`) expects
`static/site.css` to contain the utilities for the new classes. Proceed to Stage 2
to resolve this.

## Stage 2: CSS regeneration — compile and commit `static/site.css`

Run the Tailwind CLI to regenerate the compiled stylesheet, then commit the
result. The regenerated file picks up `w-full`, `md:w-auto`, `hidden`, and
`md:block` from Tailwind's utility set via template source scanning.

**Files**: `static/site.css` (regenerated, committed)

**Key changes**:

- `static/site.css` — regenerated by `scripts/build-css.sh`
  - New utilities emitted in `@layer utilities`: `hidden` (`display: none`),
    `block` (`display: block`), `w-full` (`width: 100%`), `w-auto` (`width:
    auto`). These likely already exist in the compiled output (base utilities).
  - New `md:` variant block entries: `md:block` (`display: block` at ≥768px),
    `md:w-auto` (`width: auto` at ≥768px). These may be new — no current template
    uses `md:block` or `md:w-auto`.
  - `asset_url` content hash changes automatically (`src/app/assets.rs`:
    SHA-256 of file bytes), producing a new `?v=<12-hex>` querystring. All
    template references use `{{ asset_url('site.css') }}`, so this propagates
    without manual changes.

**Tests**: None added — this is a derived artifact.

**Verify**:
```fish
./scripts/build-css.sh && git diff --exit-code -- static/site.css
```
Expected: zero exit code, confirming the regenerated file matches what will be
committed.

## What This Change Touches (and Doesn't)

| Layer | Changed? | Why |
|-------|----------|-----|
| Schema / migrations | No | No new tables, columns, or data |
| Store / repository | No | No data-access methods needed |
| Service / business logic | No | No processing or validation changes |
| Handlers / routes | No | Responsive behavior is CSS-only |
| Templates | **Yes** | Stage 1: `contact.html` + `layout.html` |
| Compiled CSS | **Yes** | Stage 2: `static/site.css` regenerated |
